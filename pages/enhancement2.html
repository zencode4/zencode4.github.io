ENHANCEMENT TWO

Algorithms & Data Structures

Algorithm Design and Data Structure Enhancements

Enhancement Overview

This enhancement focused on improving the functionality of the Grazioso Salvare Animal Rescue Dashboard by adding a search feature without changing the existing rescue-type filtering system. The goal was to allow users to search for animals by name or breed while preserving the original workflow and ensuring that the table, chart, map, and status message all remained synchronized.

Skills Demonstrated

  • Software Architecture
  • Object-Oriented Design
  • Code Refactoring
  • Maintainability
  • Professional Documentation

Artifact Description

The artifact selected for this enhancement is the Grazioso Salvare Animal Rescue Dashboard project which I originally worked on in CS 340: Client/Server Development. The dashboard already had a working interface, a MongoDB database, and a CRUD module. This gave me the material needed to review the application and determine where meaningful improvements could be made based on the capstone criteria. For this enhancement, I focused on improving the application's search capabilities by allowing users to search for animals by name or breed while preserving the existing rescue-type filtering system.

Justification for Inclusion

I selected this artifact because it gave me the opportunity to improve an existing application instead of creating something completely new. Rather than replacing the rescue-type filtering system, I added a search feature that worked alongside the existing filters. This required understanding how data moved from MongoDB into the Pandas DataFrames and how Dash callbacks updated the table, chart, map, and status message. I think this enhancement demonstrates the type of problem solving that developers encounter when they need to add new functionality without disrupting software that already works.

Reflection

The algorithms and data structures enhancement taught me that adding a new feature isn't always the difficult part. The part that actually took the most time was understanding how data moved through the application. The dashboard retrieves records from MongoDB, organizes them inside Pandas DataFrames, and then uses that data to update the table, charts, and map. At first I found it difficult to follow that process because several parts of the application were working together. Once I understood how everything was connected, adding the search feature became much easier because I knew where it belonged instead of trying to force it into the application.

Another challenge was getting the search feature and the rescue-type filters to work together. A few times I would get one working only to realize I had accidentally broken the other. I went back through the callbacks several times until both filters worked together without overriding each other. After that I spent time testing searches by name, breed, partial matches, blank searches, and rescue-type filters to make sure everything behaved as expected. I also checked that the table, chart, map, and status message all stayed synchronized after each search.

Looking back, I think this enhancement taught me more about understanding an existing application than it did about writing the search algorithm itself. Sometimes the hardest part isn't building a new feature. It's understanding how everything already fits together so you can improve the application without disrupting the functionality that's already there.
