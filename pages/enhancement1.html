Software Design & Engineering

Software Architecture, Code Refactoring, and Maintainability Improvements

Enhancement Overview

This enhancement focused on improving the software architecture, organization, and maintainability of the original Grazioso Salvare Animal Rescue Dashboard. The goal was to improve usability and code quality while preserving the application's existing functionality.

Artifact Description

The artifact selected for this enhancement is the Grazioso Salvare Animal Rescue Dashboard project which I originally worked on in CS 340: Client/Server Development. The dashboard already had a working interface, a MongoDB database, and a CRUD module. This gave me the material needed to browse through the application and decide where it made sense to improve it based on the criteria that we were tasked with. I chose this artifact because it combines a user interface, server-side programming, and database functionality into one application instead of focusing on just one area of computer science.

Justification for Inclusion

I selected this artifact because I think it is much closer to what happens in a real software development environment. Most of the time you're working on software that somebody already wrote instead of constantly starting over. This project gave me the opportunity to review an existing application, determine where improvements could be made, and build on top of the original code without changing what already worked. It also combines software engineering, database integration, and user interface development into one project, making it the strongest artifact to demonstrate growth in this area.

Reflection

The software engineering enhancement showed how software quality can go beyond just producing working code. The dashboard of the application was functional to begin with, but after I reviewed the code I started to notice areas that I could possibly improve. I was looking for places where I could improve the organization, future maintainability, and readability without changing its existing behavior. What I then did was reorganize parts of the dashboard into clearly defined interface sections, utilize reusable styling constants, replace repeated formatting throughout the application, and make the overall layout more consistent and easier to maintain in the future.

This enhancement also helped me understand the importance of separating concerns, such as having the database operations remain isolated within the CRUD module while Dash callbacks continue to manage the user interface. Instead of rebuilding existing functionality, I focused on improving the quality of the codebase itself. I also learned that centralizing colors, spacing, fonts, and other interface elements into shared style constants can make future modifications much easier instead of having duplicated code throughout the application. One of the more challenging parts of this enhancement involved the alternating row colors within the data table. Testing the updated interface showed me how small changes can have unintended side effects because the existing callback that highlighted selected columns was interfering with the row styling. Fixing that issue helped me better understand the importance of testing enhancements within the context of the application instead of evaluating individual features in isolation.

Looking back, I also think the initial code review was one of the most valuable parts of the capstone. Having to go through a previously built project and look for areas where there could be room for improvement made me think differently about the application. Instead of simply asking whether it worked, I started asking whether it was organized well, whether something could be simplified, and whether future changes would be easier or harder because of the way I originally wrote the code. Once I had those questions answered, the enhancements became much easier because I knew the changes I was making actually had a purpose.
